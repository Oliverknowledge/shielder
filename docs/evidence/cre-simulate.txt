CLI: CRE CLI version v1.32.0

Two runs. The first shows the confidential handler executing. The second
shows what happens when the secret it depends on is wrong — which is the
part that proves the secret is load-bearing rather than merely present.

Both use the evm-dry-settings target: identical to evm-settings but with
deliver:false, so the workflow runs end to end without broadcasting a
verdict to a live vault. Anyone can reproduce these without spending gas.

===============================================================================
What these show, and what they do not
===============================================================================

They show: a confidential TEE handler is registered (handlerInTee in
cre/shield-risk/main.ts) and the CLI reports the enclave it would run in;
the workflow reads a secret inside that handler and cannot proceed without
a valid one; and the enclave derives the loss independently, from the
vault's own flows and from the venue's settled PnL, then applies the user's
own on-chain rule.

They do not show a signature, because neither run is actionable: this
vault's realised loss is zero once the venue's own settlement is taken into
account, so there is nothing to attest. The signing path is evidenced
separately by the verdict that is on chain — see docs/SPONSOR_INTEGRATIONS.md.
